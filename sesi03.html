Klasifikasi & Metadata Otomatis

Merancang skema klasifikasi arsip yang logis, lalu mengotomasinya: setiap dokumen yang masuk diberi kode, deskripsi metadata, dan dipindahkan ke subfolder kategorinya.

Metode
Praktikum lab, studi kasus
Bobot tugas
10%
A

Tujuan Pembelajaran

Setelah sesi ini, Anda mampu merancang skema klasifikasi dan metadata, lalu menerapkannya secara otomatis pada alur penerimaan dokumen.

  1. Menjelaskan prinsip skema klasifikasi arsip yang baik dan jenis-jenis metadata dokumen.
  2. Merancang skema dan kode klasifikasi untuk studi kasus kelompok Anda.
  3. Memakai File.setDescription() dan PropertiesService untuk menyimpan metadata dan nomor urut.
  4. Menulis skrip yang mengklasifikasikan dokumen dan memindahkannya ke subfolder kategori secara otomatis.

Prasyarat: alur Form → Drive → Sheets dari sesi 2 sudah berjalan, karena sesi ini memperluas skrip tersebut.

C

Materi Pembelajaran

1. Skema dan kode klasifikasi arsip

Klasifikasi adalah pengelompokan dokumen berdasarkan ciri yang sama, umumnya fungsi atau pokok masalahnya, dan setiap kelompok diberi kode. Dengan klasifikasi, dokumen yang berkaitan ditemukan di satu tempat. Di lemari arsip, kode klasifikasi menentukan map mana yang dipakai. Di sistem digital, kode yang sama menentukan subfolder dan nomor arsip.

Ciri skema yang baik

PrinsipArtinyaContoh yang kurang tepat
LogisDikelompokkan berdasarkan fungsi atau pokok masalahKategori "Surat dari Pak Budi" (berdasarkan nama orang)
Saling lepasSatu dokumen hanya cocok untuk satu kategoriKategori "Penting" dan "Keuangan" yang bisa tumpang tindih
LengkapSemua jenis dokumen organisasi tertampungTidak ada kategori untuk dokumen yang sering muncul
Sederhana & konsistenMudah dipahami dan dipakai orang lain secara seragamDua puluh kategori dengan istilah yang berubah-ubah
Dapat dikembangkanMudah menambah kategori atau subkategori baruKode yang habis dan tidak bisa disisipi

Contoh skema sederhana

Berikut contoh untuk sebuah sekolah atau kampus. Skema ini hanya contoh latihan. Sesuaikan dengan studi kasus Anda, dan jika organisasinya memiliki pedoman klasifikasi resmi, rujuk pedoman tersebut.

2. Metadata dokumen

Metadata adalah data tentang data: keterangan yang menjelaskan sebuah dokumen tanpa harus membukanya. Seperti label pada map arsip, metadata membuat dokumen mudah dicari dan dipahami konteksnya.

Jenis metadataContohSumbernya
DeskriptifPerihal, pengirim, nomor surat, kategoriDiisi dari jawaban Form
AdministratifKode arsip, tanggal diterima, statusDibuat oleh skrip Anda
TeknisNama file, tipe file, ukuran, tanggal dibuatOtomatis dari Drive (getMimeType(), getSize(), getDateCreated())

Sintaks baru yang dipakai

Perhatikan: PropertiesService menyimpan nilai yang tetap ada meski skrip selesai berjalan. Nilainya selalu berbentuk teks, jadi angka harus diubah dengan Number() saat dibaca. Layanan ini cocok untuk penghitung nomor urut dan pengaturan skrip. Metadata tiap file disimpan di deskripsinya, bukan di Properties.

4. Praktikum: memperluas skrip sesi 2

Langkah 1. Siapkan Form, folder, dan Sheets

  1. Di Form, tambahkan pertanyaan pilihan ganda berjudul Kategori Surat dengan pilihan sesuai skema Anda (misalnya Umum, Kepegawaian, Keuangan, Akademik).
  2. Di folder "Arsip Surat Masuk", buat subfolder yang namanya persis sama dengan setiap pilihan kategori.
  3. Di lembar kerja Agenda, tambahkan dua kolom di akhir: Kategori dan Kode Arsip. Urutan kolom setelah perubahan: No. Agenda, Tanggal Diterima, Nomor Surat, Pengirim, Perihal, Jenis Surat, Tautan File, Kategori, Kode Arsip.

Langkah 2. Ganti isi skrip

Perbarui skrip di editor Form dengan versi berikut. Trigger dari sesi 2 tetap dipakai, karena nama fungsi utamanya sama.

// Ganti dengan ID milik Anda
const ID_SPREADSHEET = "ID_SPREADSHEET_AGENDA";
const ID_FOLDER_ARSIP = "ID_FOLDER_ARSIP";

// Skema klasifikasi: nama kategori di Form -> kode klasifikasi
const SKEMA = {
  "Umum": "UM",
  "Kepegawaian": "KP",
  "Keuangan": "KU",
  "Akademik": "AK"
};

function ambilJawaban(response) {
  const hasil = {};
  response.getItemResponses().forEach(function (ir) {
    hasil[ir.getItem().getTitle()] = ir.getResponse();
  });
  return hasil;
}

// Nomor urut per kode, disimpan permanen di PropertiesService
function nomorUrutBerikut(kode) {
  const props = PropertiesService.getScriptProperties();
  const kunci = "urut_" + kode;
  const berikut = (Number(props.getProperty(kunci)) || 0) + 1;
  props.setProperty(kunci, String(berikut));
  return berikut;
}

// Mencari subfolder; berhenti dengan pesan jelas jika tidak ada
function ambilSubfolder(induk, nama) {
  const hasil = induk.getFoldersByName(nama);
  if (!hasil.hasNext()) {
    throw new Error("Subfolder tidak ditemukan: " + nama);
  }
  return hasil.next();
}

function catatSuratMasuk(e) {
  const jawaban = ambilJawaban(e.response);

  // 1. Klasifikasi: kategori -> kode -> nomor arsip
  const kategori = jawaban["Kategori Surat"];
  const kode = SKEMA[kategori];
  if (!kode) {
    throw new Error("Kategori tidak ada di skema: " + kategori);
  }
  const nomorArsip = kode + "-" + String(nomorUrutBerikut(kode)).padStart(3, "0");  // mis. KP-001

  // 2. Pindahkan file ke subfolder kategori
  const file = DriveApp.getFileById(jawaban["Unggah File Surat"][0]);
  const induk = DriveApp.getFolderById(ID_FOLDER_ARSIP);
  file.moveTo(ambilSubfolder(induk, kategori));

  // 3. Isi metadata pada deskripsi file
  file.setDescription(
    "Kode arsip: " + nomorArsip +
    " | Kategori: " + kategori +
    " | Pengirim: " + jawaban["Pengirim"] +
    " | Perihal: " + jawaban["Perihal"]
  );

  // 4. Catat ke buku agenda
  const sheet = SpreadsheetApp.openById(ID_SPREADSHEET).getSheetByName("Agenda");
  const nomorAgenda = "SM-" + String(sheet.getLastRow()).padStart(3, "0");
  sheet.appendRow([
    nomorAgenda,
    new Date(),
    jawaban["Nomor Surat"],
    jawaban["Pengirim"],
    jawaban["Perihal"],
    jawaban["Jenis Surat"],
    file.getUrl(),
    kategori,
    nomorArsip
  ]);
}

Alurnya: kategori dari Form diubah menjadi kode lewat SKEMA, kode itu dipakai untuk membuat nomor arsip, file dipindahkan ke subfolder yang namanya sama dengan kategori, lalu metadata ditulis ke deskripsi file dan ke Sheets.

Langkah 3. Uji dan periksa hasilnya

  1. Gunakan fungsi ujiCoba() dari sesi 2, atau kirim Form sungguhan untuk setiap kategori.
  2. Di Drive, pastikan file masuk ke subfolder yang benar. Klik file, buka ikon ⓘ (Detail), lalu baca kolom deskripsi.
  3. Di Sheets, pastikan kolom Kategori dan Kode Arsip terisi dan nomor urut berjalan per kode (UM-001, UM-002, KP-001, dan seterusnya).

Dua fungsi bantu berikut berguna selama pengujian:

// Melihat semua nomor urut yang tersimpan
function lihatCounter() {
  Logger.log(PropertiesService.getScriptProperties().getProperties());
}

// Mengulang semua nomor urut dari awal (jalankan setelah selesai uji coba)
function resetCounter() {
  PropertiesService.getScriptProperties().deleteAllProperties();
}
Catatan: nomor urut tetap bertambah setiap ujiCoba() dijalankan, dan nomor bisa terlewat bila skrip gagal di tengah jalan. Jalankan resetCounter() dan hapus baris uji di Sheets sebelum pengumpulan tugas.

Tugas Praktikum Sesi 3

Skema klasifikasi dirancang bersama kelompok, sedangkan skripnya dikerjakan berpasangan. Semuanya dikumpulkan sebelum sesi 4.

  1. Rancang skema klasifikasi studi kasus kelompok dalam bentuk tabel: minimal empat kategori, dengan kode, contoh dokumen, dan alasan pengelompokan. Pastikan skema memenuhi prinsip logis dan saling lepas.
  2. Terapkan skema tersebut pada alur penerimaan dari sesi 2: pertanyaan kategori di Form, subfolder di Drive, kode arsip, dan deskripsi metadata otomatis.
  3. Uji dengan minimal dua dokumen untuk setiap kategori, lalu jalankan resetCounter() dan bersihkan baris uji sebelum mengumpulkan.
  4. Perbarui laporan progres kelompok dari sesi 2: ubah status tahap Klasifikasi & metadata, lalu tulis kendala dan rencana sesi berikutnya.
  5. Kumpulkan: tabel skema klasifikasi, tautan Form, Spreadsheet (akses lihat), dan proyek skrip, tangkapan layar subfolder Drive beserta deskripsi satu file, dan laporan progres terbaru.
