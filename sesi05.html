Pencarian & Dashboard Web App

Membangun halaman web sederhana yang mencari dokumen arsip berdasarkan metadata dan isi, sehingga dokumen yang sudah tertata di sesi sebelumnya bisa ditemukan kembali dalam hitungan detik.

Metode
Praktikum lab, live coding
Bobot tugas
10%
A

Tujuan Pembelajaran

Setelah sesi ini, Anda mampu membangun dan men-deploy Web App pencarian dokumen untuk arsip studi kasus kelompok Anda.

  1. Menjelaskan alur kerja Web App: doGet(), HTML Service, dan pemanggilan fungsi server dari browser.
  2. Menulis query pencarian untuk searchFiles() dan membedakannya dari pencarian lewat buku agenda.
  3. Membangun fungsi pencarian berdasarkan metadata (kata kunci, kategori, jenis, rentang tanggal) dan berdasarkan isi dokumen.
  4. Menampilkan hasil pencarian secara aman di halaman web, lalu men-deploy-nya sebagai Web App.

Prasyarat: skrip sesi 2 sampai 4 sudah berjalan dan lembar Agenda berisi beberapa dokumen uji, karena sesi ini mencari data yang dihasilkan skrip tersebut. Baris uji dari sesi 2 dan 3 sebaiknya sudah dibersihkan (lihat tugas sesi 3 dan 4), karena baris lama tidak punya kolom Kategori, Kode Arsip, dan Nama File.

Materi Pembelajaran

1. Mencari dokumen digital

Arsip yang rapi baru berguna bila isinya bisa ditemukan kembali. Pada sesi 2 sampai 4, setiap dokumen sudah meninggalkan jejak di tiga tempat: baris di buku agenda, nama file dan folder, serta deskripsi file. Sesi ini memanfaatkan ketiganya.

Sumber pencarianKelebihanKeterbatasan
Buku agenda (Sheets)Data terstruktur sehingga bisa disaring per kategori, jenis, dan tanggal; cepat; tautan file sudah adaHanya menemukan apa yang sudah dicatat; isi dokumen tidak ikut terbaca
Isi dokumen (fullText)Menemukan kata yang hanya ada di dalam dokumenBergantung pada indeks Drive; PDF hasil scan gambar mungkin tidak terbaca, dan file baru bisa tertunda diindeks
Nama file dan folderPola nama dari sesi 4 sudah memuat unit, jenis, tanggal, dan nomorPencocokan nama file di Drive tidak selalu seperti yang diharapkan (lihat catatan di bawah)

Karena itu Web App sesi ini menyediakan dua mode: buku agenda sebagai pencarian utama, dan isi dokumen sebagai pelengkap.

2. Sintaks query searchFiles()

DriveApp.searchFiles(query) dan folder.searchFiles(query) menerima satu teks query dan mengembalikan iterator file, sama seperti getFiles(). Query disusun dari kondisi yang dihubungkan and, or, atau not.

KondisiContohArtinya
title containstitle contains 'undangan'Nama file memuat kata tersebut
fullText containsfullText contains 'rapat'Nama, deskripsi, atau isi teks file memuat kata tersebut
mimeType =mimeType = 'application/pdf'Hanya jenis file tertentu
modifiedDate >modifiedDate > '2026-11-01T00:00:00'Diubah setelah tanggal tertentu (format tahun-bulan-hari, lalu T dan jam)
'ID' in parents'1AbC...' in parentsBerada langsung di folder tersebut
trashed =trashed = falseMengecualikan file di tempat sampah
Dua jebakan: (1) 'ID' in parents hanya mencakup isi langsung folder, tidak sampai subfolder. Karena arsip kita berlapis (Arsip → tahun → kategori), pencarian isi harus menelusuri folder tahun dan kategori satu per satu. (2) contains mencocokkan kata atau awalan kata, bukan potongan di tengah kata. Nama seperti SEK_UND_20261112_UM-001.pdf bisa tidak cocok dengan potongan "UND". Uji sendiri perilakunya, dan andalkan buku agenda untuk pencarian yang pasti.

Kata kunci dari pengguna harus di-escape. Tanda kutip tunggal di kata kunci (misalnya Pak Bahri's) akan merusak query dan menimbulkan galat. Skrip perlu menambahkan garis miring terbalik di depannya.

3. Cara kerja Web App

Web App adalah skrip yang punya alamat URL. Saat URL dibuka, Apps Script menjalankan doGet() dan menampilkan halaman HTML yang dikembalikannya. Halaman itu berjalan di browser pengguna, sedangkan fungsi yang menyentuh Drive dan Sheets berjalan di server Google.

BrowserMenampilkan Index.html; pengguna mengisi filter
→
google.script.runMemanggil fungsi server dengan filter sebagai argumen
→
Fungsi serverMembaca Sheets atau mencari di Drive
→
HasilDikirim balik ke browser dan digambar menjadi tabel

Sintaks baru yang dipakai

Data lewat google.script.run harus sederhana. Teks, angka, array, dan objek biasa bisa dikirim, tetapi objek Date tidak. Karena itu tanggal diubah menjadi teks dengan Utilities.formatDate() sebelum dikembalikan.
Jangan memasukkan data ke halaman dengan innerHTML. Perihal dan pengirim berasal dari isian Form orang lain. Bila ada yang menulis kode HTML atau JavaScript di kolom itu, innerHTML akan menjalankannya di browser pengguna. Gunakan textContent, yang memperlakukan semuanya sebagai teks biasa.

4. Praktikum: membangun Web App pencarian

Langkah 1. Uji searchFiles() di editor

Tempel fungsi berikut, jalankan, lalu lihat log. Pencarian ini menyapu seluruh Drive, bukan hanya arsip Anda. Hasilnya menunjukkan mengapa pencarian isi nanti dibatasi pada folder arsip.

function ujiPencarian() {
  // Pencarian ke seluruh Drive: semua file yang isinya memuat kata "Undangan"
  const hasil = DriveApp.searchFiles("trashed = false and fullText contains 'Undangan'");
  let n = 0;
  while (hasil.hasNext() && n < 5) {
    const f = hasil.next();
    Logger.log(f.getName() + " | " + f.getUrl());
    n++;
  }
  Logger.log(n + " file ditampilkan");
}

Langkah 2. Fungsi pencarian metadata

Fungsi ini membaca lembar Agenda, menyaring barisnya, dan mengembalikan paling banyak 50 hasil, terbaru lebih dulu. Urutan kolom mengikuti appendRow di sesi 4; bila lembar Anda berbeda, sesuaikan urutan nama pada baris const [...] = data[i].

const BATAS_HASIL = 50;

// Mencari di buku agenda. Mengembalikan array objek berisi teks saja.
function cariMetadata(filter) {
  const kata = (filter.kata || "").trim().toLowerCase();
  const sheet = SpreadsheetApp.openById(ID_SPREADSHEET).getSheetByName("Agenda");
  const data = sheet.getDataRange().getValues();
  const hasil = [];

  for (let i = data.length - 1; i >= 1; i--) {   // dari baris terbaru; baris 0 = judul kolom
    // urutan sama dengan appendRow pada sesi 4
    const [noAgenda, tglTerima, nomorSurat, pengirim, perihal, jenis,
           tautan, kategori, kodeArsip, namaFile] = data[i];

    // Date tidak bisa dikirim ke browser, jadi diubah menjadi teks
    const tgl = tglTerima instanceof Date
      ? Utilities.formatDate(tglTerima, "Asia/Jakarta", "yyyy-MM-dd")
      : String(tglTerima);

    if (filter.kategori && kategori !== filter.kategori) continue;
    if (filter.jenis && jenis !== filter.jenis) continue;
    if (filter.dari && tgl < filter.dari) continue;
    if (filter.sampai && tgl > filter.sampai) continue;

    const gabungan = [nomorSurat, pengirim, perihal, kodeArsip, namaFile].join(" ").toLowerCase();
    if (kata && gabungan.indexOf(kata) === -1) continue;

    hasil.push({
      kode: String(kodeArsip || ""),      // baris lama (sesi 2–3) belum punya kolom ini
      nama: String(namaFile || ""),
      kategori: String(kategori || ""),
      tanggal: tgl,
      keterangan: pengirim + " — " + perihal,
      tautan: String(tautan || "")
    });
    if (hasil.length >= BATAS_HASIL) break;
  }
  return hasil;
}

function ujiMetadata() {
  Logger.log(JSON.stringify(cariMetadata({ kata: "rapat" }), null, 2));
}

Langkah 3. Fungsi pencarian isi dokumen

Fungsi ini menelusuri folder tahun dan kategori, lalu memanggil searchFiles() pada tiap folder kategori. Kode arsip diambil dari deskripsi file yang diisi pada sesi 3.

// Mencari kata di dalam isi dokumen, hanya pada folder arsip
function cariIsi(filter) {
  const kata = (filter.kata || "").trim();
  if (!kata) {
    throw new Error("Isi kata kunci untuk pencarian isi dokumen.");
  }
  // tanda kutip dan garis miring dalam kata kunci harus di-escape agar query tidak rusak
  const aman = kata.replace(/\\/g, "\\\\").replace(/'/g, "\\'");
  const query = "trashed = false and fullText contains '" + aman + "'";

  const hasil = [];
  const folderTahun = DriveApp.getFolderById(ID_FOLDER_ARSIP).getFolders();
  while (folderTahun.hasNext()) {
    const tahun = folderTahun.next();
    const folderKategori = tahun.getFolders();
    while (folderKategori.hasNext()) {
      const kat = folderKategori.next();
      if (filter.kategori && kat.getName() !== filter.kategori) continue;

      const files = kat.searchFiles(query);
      while (files.hasNext() && hasil.length < BATAS_HASIL) {
        const f = files.next();
        const deskripsi = f.getDescription() || "";
        const cocok = deskripsi.match(/Kode arsip: (\S+)/);
        hasil.push({
          kode: cocok ? cocok[1] : "",
          nama: f.getName(),
          kategori: kat.getName(),
          tanggal: Utilities.formatDate(f.getDateCreated(), "Asia/Jakarta", "yyyy-MM-dd"),
          keterangan: deskripsi,
          tautan: f.getUrl()
        });
      }
    }
  }
  return hasil;
}

Langkah 4. doGet() dan halaman Index.html

Tambahkan doGet() dan ambilOpsiFilter() ke berkas skrip. Dropdown kategori dan jenis diisi dari SKEMA dan SINGKATAN_JENIS, sehingga otomatis ikut bila skema Anda berubah.

// Dijalankan saat URL Web App dibuka di browser
function doGet() {
  return HtmlService.createHtmlOutputFromFile("Index")
    .setTitle("Pencarian Arsip Surat Masuk");
}

// Mengisi pilihan dropdown dari konstanta yang sudah ada
function ambilOpsiFilter() {
  return {
    kategori: Object.keys(SKEMA),
    jenis: Object.keys(SINGKATAN_JENIS)
  };
}

Langkah 5. Deploy sebagai Web App

  1. Jalankan ujiMetadata sekali dari editor dan setujui izin akses yang diminta.
  2. Klik Deploy → New deployment, pilih jenis Web app.
  3. Isi Execute as dengan Me. Untuk Who has access, pilih pembatasan paling ketat yang masih memungkinkan dosen menguji (misalnya hanya pengguna di domain Anda). Nama opsi bisa sedikit berbeda menurut versi editor.
  4. Klik Deploy, lalu salin URL yang berakhiran /exec.
Hati-hati dengan hak akses. Dengan Execute as: Me, semua orang yang boleh membuka Web App membaca arsip dengan hak akses Anda. Jangan membuka akses untuk publik pada arsip yang berisi data nyata.
Perubahan kode tidak otomatis tampil di URL /exec. Setelah mengubah kode, buka Deploy → Manage deployments, ikon pensil, pilih New version, lalu Deploy. URL /dev selalu memakai kode terbaru tetapi hanya bisa dibuka oleh editor proyek, jadi cocok untuk menguji.

Langkah 6. Uji dan periksa

  1. Buka URL Web App dan pastikan dropdown Kategori dan Jenis terisi.
  2. Cari dengan kata kunci yang ada di perihal; lalu coba kombinasi kategori dan rentang tanggal.
  3. Ganti mode ke isi dokumen, cari satu kata yang ada di dalam file uji, lalu bandingkan hasilnya dengan mode buku agenda.
  4. Klik Buka pada salah satu hasil dan pastikan file di Drive yang terbuka sesuai.
  5. Cari kata yang tidak ada dan pastikan muncul "0 dokumen ditemukan", bukan halaman kosong atau galat.

Tugas Praktikum Sesi 5

Rancangan antarmuka didiskusikan bersama kelompok, sedangkan Web App dikerjakan berpasangan. Semuanya dikumpulkan sebelum sesi 6.

  1. Rancang antarmuka pencarian untuk studi kasus kelompok. Tuliskan siapa penggunanya, tiga pencarian yang paling sering mereka lakukan, filter yang disediakan, dan kolom hasil yang ditampilkan.
  2. Bangun dan deploy Web App yang mencari lewat buku agenda dan isi dokumen, dengan kategori dan jenis yang sesuai skema kelompok Anda.
  3. Tambahkan satu penyesuaian yang relevan dengan studi kasus, misalnya filter unit pengirim, pengurutan hasil, atau kolom tambahan, dan jelaskan alasannya.
  4. Uji dengan minimal lima pencarian berbeda, termasuk satu yang tidak menghasilkan apa-apa. Catat hasilnya dalam tabel pengujian.
  5. Perbarui laporan progres kelompok: ubah status tahap Pencarian, lalu tulis kendala dan rencana sesi berikutnya.
  6. Kumpulkan: URL Web App, proyek skrip (akses lihat), tangkapan layar hasil pencarian untuk mode agenda dan mode isi, tabel pengujian, dokumen rancangan antarmuka, dan laporan progres terbaru.
